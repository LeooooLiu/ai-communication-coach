# GPT-6 Luna behavior run — 2026-09-27

## Scope

This run checks ten anonymized cases derived from real project conversations. It tests user-visible behavior and interaction cost rather than exact wording or hidden classification labels.

## Configuration

- Model: `gpt-6-luna`
- Reasoning effort: `low`
- Codex CLI: `0.155.0-alpha.16`
- Behavior runs: two fresh ephemeral sessions per case
- Invocation: explicit `$ai-communication-coach`
- Side effects: disabled; each session produced the first response it would send before execution

The initial run passed 19 of 20 observable responses. One response to “inspect first, decide later” asked a planning-process question before doing the inspection.

## Correction and focused regression

The Skill now classifies understanding risk for the **next authorized step**. A later implementation branch no longer blocks a clear inspection or evidence-gathering stage.

Focused reruns:

- `inspect-before-plan-decision`: 4/4 responses began inspection without a current user question.
- immediate material branch control: 4/4 responses asked for the one missing version choice before editing.

This preserves necessary clarification while removing the premature question found in the initial run.

## Implicit routing check

Six isolated routing simulations omitted the explicit Skill mention:

- 3/3 communication-review, retrospective, and consequential-ambiguity requests selected `ai-communication-coach`.
- 3/3 simple translation, exact title edit, and factual definition requests skipped it.

The routing result supports the current description and `allow_implicit_invocation: true` policy. Runtime traces do not expose a separate authoritative “Skill loaded” event, so this remains a selection simulation rather than proof of every host application's routing behavior.

## Evaluator correction

An exploratory grader initially compared internal labels such as `executing` versus `repairing_or_changing`. It marked semantically correct responses as failures even when the action, attribution, and interaction cost were identical. Release evaluation now grades observable behavior:

- whether work proceeds or waits correctly;
- whether a real question is asked;
- whether the right party or dependency is blamed;
- whether action and external boundaries are respected.

## Conclusion

This configuration meets a single-model beta threshold for the tested cases. It does not establish cross-model stability. A second model family and real multi-turn execution runs are still required before making a broad portability claim.

# ISO/IEC/IEEE 29148:2018 — local source note

Source: <https://www.iso.org/standard/72089.html>

Access status: the complete standard is sold by ISO. This local note contains bibliographic information, paraphrases of the official public preview, and the Skill's operational interpretation. It does not reproduce the standard.

## Public scope

ISO/IEC/IEEE 29148:2018 covers requirements engineering processes and the information those processes produce across the life cycle of systems, software products, hardware products, and related services. It describes how requirements are discovered, developed, analyzed, validated, verified, communicated, documented, and managed.

The 2018 edition was reviewed and confirmed in 2024. ISO currently lists it as due to be replaced by a later edition under development.

## Concepts used by this Skill

- A requirement connects a need with relevant conditions and constraints.
- Precision matters when several implementations could satisfy the same vague sentence.
- Validation asks whether the stated requirements describe the result stakeholders actually intend.
- Verification examines whether requirements are well formed and can be assessed.
- Traceability connects a requirement to the need that produced it and to later implementation or evidence.

## Operational translation

For ordinary AI requests, use these concepts proportionally:

1. Identify the intended outcome and the artifact or action that would produce it.
2. Separate real constraints from background information and examples.
3. Ask only when a missing choice would create materially different compliant results.
4. Give completion an observable test, file, state, or evidence source.
5. Preserve the link between a user decision, the work performed, and the evidence used to judge it.

This note supports task communication. It is not a substitute for the full standard in formal systems or software engineering work.
